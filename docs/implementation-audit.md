# 实现与 UI 接线审计（更新至 2026-09-07）

范围：CoreHandle → Core/turn → writer/SQLite → 配置/模型与工具注册 → server WebSocket → app.js。以当前源码和行为测试为准，未调整页面视觉风格。

## 已修复

| 问题与触发场景 | 修复 |

| 修改模型/工具表单后保存，旧 JSON 覆盖新值 | 表单同步 JSON；用户明确编辑 JSON 时才优先使用它；非法 JSON 阻止保存 |

## 仍未完整覆盖的能力与边界

这些是后续工作，不应理解为本轮已经实现。

1. **持久化回执/幂等重发（优先处理）**：Core 已有 Ack.durable 和 session_resend，但 server 丢弃发送回执，UI 没有稳定 client_id、待确认队列或重连重发。此次只修复“已断线时清空输入”；发送与断线恰好交错时仍不能保证消息确认。
2. **同一 WebSocket 的长命令**：ws_loop 仍 await handle，探活等操作会阻塞该连接继续收发。其他标签页的普通控制不被生命周期锁阻塞，但单标签页的控制响应仍应独立设计与测试。
3. **恢复快照与实时事件的一致边界**：seq 去重解决重复历史，不等于完整的内存/磁盘/流式一致快照。writer 尚未落盘的正文、重连前的部分 delta 不能全部由 boot 重建；磁盘降级提示仍是必要信号。
4. **图编辑能力**：Core 的边、分组、属性、来源/置信度、render/view/sketch 以及新建节点/字段操作，尚未全部提供 UI 编辑入口。当前 SVG 仍不按词表绘制不同形状；词表修复作用于 Mermaid 源码。嵌套分组也未完成完整可视布局验证。
5. **模型注册体验**：三个角色及已有 provider 可表单编辑；新增/移除 provider 仍通过高级 JSON。数值范围、空模型名、URL 有效性等缺少完整语义校验；本轮没有加入真实供应商探活。
6. **会话观测**：Core 的角色账本和工具指标并未完整、实时地呈现；mode 在进程重启后也没有独立的持久化切换事件。此次只保留同一会话配置重建时的 mode。

## 回归入口与证据边界

```sh
cargo test --all-targets
node --test tests/ui.test.cjs
```

- `tests/chain_scenarios.rs` 将原本仅在主程序执行的 40 个链路场景纳入 cargo test，防止“编译了但没有运行”。
- `tests/reaudit_probe.rs`：原有 11 个场景，包含 SQLite 重开、上下文去重、折叠、关闭/持久化顺序、工具超时、取消、重发及 checkpoint。
- `src/server.rs`：配置重建与历史保留、失败保护、首次密钥启动、答案 HTML、草稿与路径边界。
- `src/markdown.rs`：危险协议回归；该测试在修复前实际失败，修复后通过。
- `tests/ui.test.cjs`：执行真实 app.js 处理函数，使用轻量 DOM 替身检查表单命令、JSON 冲突、恢复状态、事件去重、断线输入、停止轮次、根目录与循环图边界。
  
当前验证：`cargo test --all-targets` 全部通过（12 项库单测、1 项完整链路场景、2 项真实协议映射、11 项恢复与持久化回归）；`node --test tests/ui.test.cjs` 的 18 项前端行为测试通过。Smart Fetch 另有正文去噪、Markdown 结构、相对链接绝对化和非 UTF-8 解码回归；未使用真实 API 密钥发起模型调用。
